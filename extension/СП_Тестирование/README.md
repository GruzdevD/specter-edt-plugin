# СП_Тестирование — EDT-расширение 1С (UI-адаптер + живой мост)

**Единый источник истины для BSL-кода расширения** — этот репозиторий
`specter-edt-plugin` (`extension/СП_Тестирование/src`). `src/` — метаданные EDT-расширения
`СП_Тестирование` (adopted-объекты конфигурации + собственные модули `СП_*`). Рабочая
копия, применяемая к ИБ, живёт в EDT-workspace — **изменяются
здесь (в `src/`), а в workspace переносятся скриптом синхронизации**. Ручное редактирование
двух копий недопустимо.

> **Версия расширения — общая с плагином**: `<version>` в `Configuration.mdo` (сейчас
> `0.2.0`) синхронизируется с версией релиза (тег `v*`, см. `release.yml`) — версии не
> расходятся.

> Статус на текущий этап: **код отрефакторен для явной конфигурации; развёртывание на
> рабочую ИБ АУФ и проверка на живом тонком клиенте — ОТДЕЛЬНЫЙ согласованный шаг**,
> вне этого захода. Всё, что требует живого 1С, помечено `[НЕ ПРОВЕРЕНО на 1С]`.

## Что это

Два связанных контура в одном расширении:

1. **Живой мост команд Runner ↔ реальный UI** (агент). Плагин `ru.ozon.uitp.e2e` (см.
   `uitp-edt-plugin`) запускает тонкий клиент АУФ со стартовой опцией
   `SPECTER_START_BRIDGE|outDir=<каталог обмена>`. Расширение в
   `Configuration/ManagedApplicationModule.bsl` при `&После("ПриНачалеРаботыСистемы")`
   видит маркер и открывает adopted `ФормаСписка` справочника «Контрагенты»; её
   `ПриОткрытии` (`Catalogs/Контрагенты/Forms/ФормаСписка/Module.bsl`) исполняет команды
   из файлового канала на **реальном слое UI** (`ЭтаФорма.Элементы.Найти(...).Видимость`).
   Файловый канал отвечает только за **доставку**; семантика команд — канонический
   `UiProtocol`.
2. **Фаза A / UiAdapter-фасад** (`СП_Адаптер`, `СП_ТестовыйКлиент`,
   `СП_Протокол`, `СП_СправочникИмен`, `СП_ТестовыеДанные`) — целевой
   адаптер по ADR-002/003. Часть поверхности `[НЕ ПРОВЕРЕНО на 1С]`.
   `СП_УправлениеФормами` — **legacy** programmatic-демо (работа с объектной моделью
   и данными; НЕ является доказательством реальных UI-действий).

## Конфигурация (без абсолютных путей и учётных данных в коде)

Каталог обмена и маркер автозапуска задаются **стартовой опцией клиента**, которую
формирует EDT-плагин:

```
/C "SPECTER_START_BRIDGE|outDir=/абсолютный/путь/к/каталогу/обмена"
```

- значение целиком доступно в `ПараметрЗапуска` на клиенте;
- BSL-агент разбирает `outDir=` и строит пути к файлам обмена
  (`bridge-commands.json`, `bridge-result-<runId>.json`, `bridge-log.txt`);
- если `outDir` не передан — агент выдаёт **понятную ошибку**, а не переходит на скрытый
  локальный путь;
- учётные данные (например пользователь ИБ при автовходе плагина) в BSL не содержатся —
  они задаются в конфигурации EDT-плагина (`uitp-edt-plugin`), не в репозитории.

## Структура

```
src/
├── Configuration/               # Configuration.mdo + ManagedApplicationModule.bsl (автозапуск по маркеру)
├── Catalogs/Контрагенты/       # adopted: ФормаСписка (агент моста), ФормаЭлемента
├── CommonModules/
│   ├── СП_Адаптер/        # BSL-проекция канонической границы UiAdapter (фасад)
│   ├── СП_Протокол/       # канонический UiProtocol (jsonrpc-обёртка)
│   ├── СП_СправочникИмен/ # реестр «стабильное имя → элемент/реквизит» (kind=name)
│   ├── СП_ТестовыеДанные/ # серверные data-директивы setup/teardown
│   └── СП_ТестовыйКлиент/ # UI-действия поверх тестового клиента / Менеджера тестирования
└── DataProcessors/СП_УправлениеФормами/  # LEGACY programmatic-демо (не UI-доказательство)
```

## Синхронизация с EDT-workspace (единый источник истины)

- **Направление:** репо (`src/`) → workspace (`afm.СП_Тестирование/src`).
- **Команда сверки расхождений (без записи):** `scripts/sync-afm-ozon-ui.sh --check`
- **Команда переноса:** `scripts/sync-afm-ozon-ui.sh` (нужно право записи в workspace и
  закрытый EDT — `workbench.xmi`/metadata не трогаются, переносятся только `src/`).

Любая воспроизводимая сборка/применение к ИБ выполняется только после переноса в workspace
и является отдельным согласованным шагом (правила безопасности проекта: не менять рабочую
ИБ АУФ и рабочий EDT-workspace без явного разрешения).

## Проверки

- Синтаксис BSL `[НЕ ПРОВЕРЕНО на 1С]` — проверяется после переноса в workspace через
  `revalidate_objects`/компиляцию EDT.
- Живой прогон на тонком клиенте АУФ `[НЕ ПРОВЕРЕНО на 1С]` — ручной/согласованный шаг.
